# Plan: Regenerate the frontend API types from the current backend (#25)

Status: Approved
Layer: frontend

## Goal
`PawsPost.Web/src/api/schema.d.ts` matches the OpenAPI document of the merged `main` (backend #21, #2 and #18, main at 7ce6bb7). It then contains the pet-ads list endpoint, the details endpoint, the `Location` header on create, and a required `title`. Nothing else changes: no screen, no behavior, no test, no package.

## Approach
Run the existing generator once (`npm run gen:api` from `PawsPost.Web`) against an API started from the merged `main`, and commit only the regenerated `schema.d.ts`. The generator scripts are not changed. The file is never edited by hand (`.claude/rules/frontend.md`). Because this is a generated file, the checks are: the generated content is what the issue expects, nothing else in the repo changed, and every existing check still passes.

Explained simply: `schema.d.ts` is a TypeScript description of the API. The generator downloads the API's OpenAPI document (`/openapi/v1.json`) and turns it into types. So the API must be running and must be the right version, otherwise we generate wrong types.

## Decisions
Recommended defaults, so the user can answer "go with suggestions":
1. The API is started by the developer for this step only, from the merged `main`, with `dotnet run --project PawsPost --launch-profile http` (from the repo root; `../PawsPost` from `PawsPost.Web`). It is stopped afterwards. (Decided default, from the issue.)
2. If anything is already listening on port 5280, the developer agent does NOT kill it. It stops and asks the user (see "Running the generator safely").
3. Any difference from the expected diff list is a stop-and-ask, not a fix.
4. No new tests, no new npm package, no change to scripts, tsconfig, `package.json` or lock file.
5. If a frontend file stops compiling, apply the smallest fix; if it is more than trivial, stop and report.
6. The commit message is exactly `chore: regenerate API types from the current backend (#25)`.

## API endpoints
No new endpoints are used by code and none are created. This plan only updates the types of existing backend endpoints. After regeneration `schema.d.ts` must describe these (source: the running merged `main`):

| Method | Route | Auth | Request | Response | Status codes |
|---|---|---|---|---|---|
| GET | /api/pet-ads | public | query `page`, `pageSize`, `species`, `type` | `PetAdListResponse` (`items` of `PetAdListItemResponse`, `totalCount`, `page`, `pageSize`) | as generated |
| GET | /api/pet-ads/{id} | public | path `id` | `PetAdDetailsResponse` (no `ownerId`) | as generated |
| POST | /api/pet-ads | logged in | `CreatePetAdRequest` (`title` required) | `PetAdResponse` (`title` required), `201` declares a `Location` header | as generated |

The status codes are whatever the generator writes from the backend. They are not decided here and must not be edited.

## Running the generator safely
The generator does not start the API. It reads the URL from the `http` profile in `PawsPost/Properties/launchSettings.json`, which is `http://localhost:5280`.

Before starting:
1. Confirm the checkout is the merged `main`: `git status` is on `main`, `git log -1` shows 7ce6bb7 or a later commit that contains it, and the working tree has no changes to tracked files (untracked docs files are fine). If `main` has moved, that is fine, but note the new commit in the PR.
2. Check whether something already uses port 5280. A `PawsPost.exe` from a Visual Studio debug session may already be running there, and it may have been built from an OLD branch. Look without touching it: in PowerShell `Get-NetTCPConnection -LocalPort 5280 -State Listen -ErrorAction SilentlyContinue` (read-only), and optionally `Get-Process PawsPost -ErrorAction SilentlyContinue`.
3. If port 5280 is in use, do not kill, stop or restart anything. Report the process name and id to the user and ask what to do (for example the user stops their debug session, or says the running API is known to be the merged `main`). The developer agent never kills a process, including one it started in an earlier step; it asks the user to stop it, or ends the process only through the same terminal session it started when that is the clean Ctrl+C of its own `dotnet run`.
4. If the port is free, start the API: `dotnet run --project PawsPost --launch-profile http` (repo root) in its own terminal, and wait for the "Now listening on: http://localhost:5280" line.

Confirm the running API really serves the merged `main` before generating. Fetch `http://localhost:5280/openapi/v1.json` (for example `Invoke-RestMethod` or `curl`, read-only) and check that it contains all of:
- the path `/api/pet-ads/{id}` (from #18),
- the path `/api/pet-ads` with a `get` operation having query parameters `page`, `pageSize`, `species` and `type` (from #2),
- the schema `PetAdDetailsResponse` (from #18),
- the schema `PetAdListResponse` and `PetAdListItemResponse` (from #2),
- `title` listed in `required` of `CreatePetAdRequest` and `PetAdResponse` (from #21).

If any item is missing, the running API is stale (built from an older branch). Stop and ask the user. Do not generate, and do not kill the process.

After generating, stop the API. If the developer agent started it with `dotnet run`, stop it with Ctrl+C in that terminal (it then ends its own process). Confirm port 5280 is free again with the same read-only check. Reason: a running API locks the backend build output, which would break `dotnet build`.

Then run, from `PawsPost.Web`: `npm run gen:api`. It prints `Wrote src/api/schema.d.ts from http://localhost:5280/openapi/v1.json`. If it prints "Is the API running?", the API is not reachable: re-check, do not change the scripts.

## What the diff must and must not contain
Check by reading `git diff -- PawsPost.Web/src/api/schema.d.ts` and comparing it to this list.

Expected additions (from the issue):
- Path `/api/pet-ads/{id}` with a `get` operation returning `PetAdDetailsResponse`.
- `get` operation on `/api/pet-ads` with query `page`, `pageSize`, `species`, `type`, returning `PetAdListResponse`.
- Schemas `PetAdListResponse` (`items`, `totalCount`, `page`, `pageSize`), `PetAdListItemResponse` and `PetAdDetailsResponse`. `PetAdDetailsResponse` has no `ownerId`.
- `title` as a required field in `CreatePetAdRequest` and `PetAdResponse`.
- A `Location` header declared on the `201` response of `POST /api/pet-ads`.
- Closely related generated detail that follows from those: new operation names under `operations`, new `parameters` entries, and new response/`404`/`400` entries for the new operations. These are fine only when they belong to the endpoints and schemas above.

Anything else is a stop-and-ask, in particular:
- any removed line that is not part of an obvious rewrite of the same type (for example the `PetAdResponse` block gaining `title`),
- any change to the auth types or paths (`/api/auth/*`, `LoginRequest`, `RegisterRequest`, `UserResponse`),
- any change to `/api/health`, `HealthResponse`, `ProblemDetails` or `ValidationProblemDetails`,
- a header comment or formatting change that is not explained by the generator version.

If the diff has an unexpected change, do not edit the file to remove it and do not commit. Report it to the user with the exact lines. It may mean the backend has an unrelated change, or the generator version drifted.

Also confirm every item of the issue's acceptance criteria 3 to 5 is true in the file (a `Grep` for `PetAdListResponse`, `PetAdListItemResponse`, `PetAdDetailsResponse`, `"/api/pet-ads/{id}"`, `location`, and `title: string;` inside the two request/response schemas).

## Line endings and formatting
The generator writes the file with the line endings Node produces on this machine (CRLF on Windows). Git may show a CRLF warning. This is expected.
- Do not run `npm run format` or `prettier --write` on `schema.d.ts`, and do not convert line endings by hand. That would be a hand edit of a generated file and would make the diff noisy.
- Prettier must pass without rewriting it: use `npx prettier --check --end-of-line auto src` (the `format:check` script fails locally on Windows only because of line endings, as the issue says). If Prettier reports `schema.d.ts` as unformatted for a reason other than line endings, stop and ask (the repo may need it in an ignore file, which is a separate decision, not part of this plan).
- Compare the line endings of the regenerated file with the version on `main` (`git diff --stat` size should look like a real content change, not the whole file rewritten). If the whole file shows as changed only because of line endings, stop and ask.

## Diff scan for hand edits
After generation and any fix, run `git status --short` and `git diff --stat`. The only modified path must be `PawsPost.Web/src/api/schema.d.ts`. Specifically:
- `git diff --name-only` lists exactly one file.
- No other tracked file under `PawsPost.Web`, `PawsPost`, `PawsPost.Tests`, `docs` or `templates` is modified. The untracked docs files from other issues (`docs/issues/*-frontend.md`, `docs/meeting-notes/2026-11-14-*.md`) must not be staged. Stage only `schema.d.ts`, by explicit path.
- As a second proof of "no hand edit", run `npm run gen:api` a second time (API still running, before stopping it) and check that `git diff` is identical to before, i.e. the generator output is stable and reproducible. If you stop the API first, skip this check rather than starting it again.

## If a frontend file stops compiling
Not expected. If `npx tsc -b` fails after regenerating:
1. Read the error. If the cause is the new required `title` or a renamed type in a file that uses the API types, make the smallest correct fix in that file (correct types or real handling). No `any`, no `@ts-*`, no cast to hide the error, no edit of `schema.d.ts`.
2. Put the fix in a separate commit: `fix: adapt to regenerated API types (#25)`.
3. If the fix is more than trivial (more than a line or two in one file, a behavior change, or several files), stop and report to the user. Do not continue.
4. A test that fails is never deleted, skipped or weakened. Stop and report.

## Risks and open questions
Open questions: none that block, if the user accepts the recommended defaults in "Decisions" ("go with suggestions").

Risks:
- Stale API on port 5280. A `PawsPost.exe` from an earlier debug session can be running on the same port and be built from an OLD branch. Generating from it would produce wrong types. The plan verifies the OpenAPI content before generating. If the check fails or the port is taken, the developer agent stops and asks. It never kills a process, because the process may be the user's own debug session.
- Running API locks backend build output. Stop the API right after generating, before any `dotnet build`, `dotnet test` or `dotnet format`.
- Generator version drift. `openapi-typescript` is `^7.13.0`; if the installed version differs from the one that produced the current file, unrelated formatting changes can appear in the diff. These are an unexpected diff and a stop-and-ask. No package is added or upgraded by this plan.
- Windows line endings. See "Line endings and formatting". `npm run format:check` may fail locally for that reason only; use `--end-of-line auto`.
- This issue blocks #19 (home page list) and #20 (details page). Dependency #18 is merged, so nothing blocks this plan.

Note (not part of this plan, no action here): the repo copy `docs/issues/get-pet-ad-details-backend.md` on `main` is older than GitHub issue #18. A docs commit (4226d1e) that exists only on the merged branch did not reach `main`. It needs separate handling by the user and is not changed by this issue.
